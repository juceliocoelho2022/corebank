# CoreBank

**CoreBank** is a production-oriented **Banking as a Service (BaaS)** portfolio backend built with Java 21 and Spring Boot. Version **0.1.0** establishes the domain and persistence foundation for customers and bank accounts before later releases add transfers, ledger accounting, idempotency, event streaming, resilience, security, and observability.

## What v0.1 demonstrates

- Java 21 and Spring Boot 3
- REST APIs with Bean Validation
- Modular-monolith boundaries
- PostgreSQL persistence with Spring Data JPA
- Database migrations with Flyway
- Database-backed deterministic account-number generation
- Optimistic locking with `@Version`
- RFC 9457-style `ProblemDetail` errors
- Swagger / OpenAPI documentation
- Actuator health endpoint
- Unit, MVC, and PostgreSQL integration tests
- Testcontainers
- JaCoCo coverage reporting
- Docker Compose local infrastructure

## Architecture

```text
com.corebank
├── account
│   ├── domain
│   ├── application
│   ├── infrastructure
│   └── web
├── customer
│   ├── domain
│   ├── application
│   ├── infrastructure
│   └── web
├── shared
│   ├── config
│   └── exception
└── CoreBankApplication
```

The application is intentionally a **modular monolith** in v0.1. The domain stays simple to run and test while package boundaries make future extraction into services possible without introducing distributed-system complexity too early.

## Domain rules

### Customer

- unique document
- unique email, case-insensitive at database level
- name between 3 and 120 characters

### Account

- default branch: `0001`
- default currency: `BRL`
- initial status: `ACTIVE`
- initial balance: `0.00`
- account number generated by PostgreSQL sequence beginning at `10000001`
- non-negative `NUMERIC(19,2)` balance
- optimistic locking with JPA `@Version`

Supported statuses:

```text
ACTIVE
BLOCKED
CLOSED
```

## Local setup

Copy the environment template if you want to override defaults:

```bash
cp .env.example .env
```

Start PostgreSQL:

```bash
docker compose up -d postgres
```

Run the application:

```bash
mvn spring-boot:run
```

The API will be available at:

```text
http://localhost:8080
```

## API

### Create customer

```bash
curl -i -X POST http://localhost:8080/api/v1/customers \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "Ana Silva",
    "document": "12345678901",
    "email": "ana.silva@example.com"
  }'
```

### Get customer

```bash
curl http://localhost:8080/api/v1/customers/<customer-id>
```

### Create account

```bash
curl -i -X POST http://localhost:8080/api/v1/accounts \
  -H 'Content-Type: application/json' \
  -d '{
    "customerId": "<customer-id>"
  }'
```

### Get account

```bash
curl http://localhost:8080/api/v1/accounts/<account-id>
```

### Get balance

```bash
curl http://localhost:8080/api/v1/accounts/<account-id>/balance
```

Run the complete verification pipeline:


## Error contract

API failures use `application/problem+json` with Spring `ProblemDetail`.

Typical statuses:

- `400` invalid request, malformed JSON, validation or malformed UUID
- `404` customer/account not found
- `409` uniqueness/integrity conflict
- `500` unexpected failure with sanitized details

## Database migration

Flyway exclusively manages DDL. Hibernate runs with:

```text
ddl-auto: validate
```

The first migration creates:

- `customers`
- `accounts`
- `account_number_seq`
- uniqueness constraints and indexes
- foreign key from account to customer
- non-negative balance constraint

## Portfolio intent

CoreBank is designed to demonstrate backend engineering decisions expected in transactional systems: explicit domain rules, database invariants, deterministic identifiers, controlled error contracts, transaction boundaries, concurrency protection, integration testing, and a deliberate path toward event-driven architecture.
